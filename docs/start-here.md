# เริ่มเรียนจาก README แล้วก๊อปโค้ดไปรัน

[กลับสารบัญ](../README.md) · [ตรวจความพร้อมบท 00](../lessons/00-setup/README.md)

ใช้ notebook ที่ถนัดได้เลย ขั้นตอนตัวอย่างของหลักสูตรใช้ **Jupyter** และโค้ด Python หลักใช้กับ **Google Colab** ได้ด้วย GitHub เป็นหน้าอ่านคำอธิบายและคัดลอกโค้ด ส่วน notebook เป็นที่รันและเก็บการทดลอง

## 1. เปิด notebook เปล่า

**ถ้าใช้ Jupyter อยู่แล้ว:** เปิดแบบเดียวกับที่ใช้เรียน NumPy, pandas และ Matplotlib สร้าง notebook ใหม่ในโฟลเดอร์สำหรับเรียน ML แล้วตั้งชื่อ เช่น `ml-00.ipynb` ผู้ที่ติดตั้ง repo ด้วย uv แล้วใช้คำสั่งเปิด Jupyter ตาม [คู่มือติดตั้ง](setup.md) เดิมได้

**ถ้าเลือก Colab:** เปิด [Google Colab](https://colab.research.google.com/) สร้าง notebook ใหม่แล้วตั้งชื่อ ใช้ runtime แบบ CPU ได้ทั้งหลักสูตร Python; ตัวอย่าง Mojo อยู่ในคู่มือเสริมแยกต่างหาก

เลือกใช้หนึ่งโปรแกรมต่อการทดลอง ไม่จำเป็นต้องทำตามทั้งสองโปรแกรม การคัดลอก Python จาก README ทำได้โดยไม่ต้อง clone repo หรือติดตั้ง Git, WSL และ uv

## 2. คัดลอกโค้ดบท 00 มาตรวจเครื่องมือ

เปิด [README บท 00](../lessons/00-setup/README.md) คัดลอกบล็อกที่ระบุ `python` ทั้งชุดลง **Code cell** แล้วกด **Shift+Enter** หากรันผ่านแล้ว เริ่มบท 01 ได้เลย ไม่ต้องติดตั้งแพ็กเกจซ้ำทุกบท

หากไม่มีแพ็กเกจหรือรุ่นไม่ตรงกับหลักสูตร ให้เพิ่ม Code cell สำหรับติดตั้งก่อน แล้วรัน:

```python
%pip install numpy==2.2.6 pandas==2.3.2 scikit-learn==1.7.1 matplotlib==3.10.3 scipy==1.16.1 joblib==1.5.1
```

นี่เป็นคำสั่งของ notebook ที่ใช้ Python/IPython ไม่ใช่โค้ดสำหรับบันทึกในไฟล์ `.py` และจะติดตั้งลง environment ของ kernel ปัจจุบัน หากใช้ environment ที่แชร์กับงานอื่นและต้องรักษารุ่นแพ็กเกจของงานนั้น ให้สร้าง environment ของหลักสูตรตาม [setup](setup.md) แทน

หลังติดตั้ง ให้ restart kernel ใน Jupyter หรือ restart session/runtime ใน Colab แล้วรันโค้ดบท 00 ใหม่ตั้งแต่ต้น หลักสูตรรองรับ Python 3.11–3.13; ถ้าเครื่องใช้รุ่นอื่นให้ดูวิธีเตรียม Python ในคู่มือติดตั้ง หากติดตั้งด้วย uv ตาม repo ไว้แล้ว ให้ข้าม cell `%pip` นี้ได้

## 3. เรียนทีละบทจาก GitHub

1. เปิด README ของบทนั้น อ่านโจทย์และแนวคิด แล้วคาดการณ์ผลก่อนรัน
2. คัดลอกบล็อก `python` ทั้งชุด รวม import และฟังก์ชัน ไป notebook ใหม่ เช่น `ml-01.ipynb`
3. รันด้วย Shift+Enter แล้วอ่านคำอธิบายผลใต้โค้ดใน README เทียบกับ output ของตัวเอง
4. เปลี่ยนตัวแปรหนึ่งอย่าง รันใหม่ และเขียนสิ่งที่สังเกตได้ลง Markdown cell
5. ทำแบบฝึกหัดก่อนเปิดแนวคำตอบ แล้วบันทึก notebook

โค้ดหลักแต่ละบทเตรียมข้อมูลเอง รันได้โดยไม่อาศัยตัวแปรจากบทก่อน ครั้งแรกให้คัดลอกทั้งบล็อกเพื่อให้ส่วน import/ฟังก์ชันครบ เมื่อทดลองใหม่ให้ Restart Kernel → Run All เพื่อไม่ใช้ตัวแปรที่ค้างจากรอบก่อน

บล็อก `bash` เป็นคำสั่ง terminal สำหรับผู้ที่ใช้ไฟล์ใน repo ส่วนนี้พับไว้เป็นทางเลือกในแต่ละบท ไม่ต้องคัดลอกมาวางใน Code cell Python

## เก็บงานและผลทดลอง

- บันทึก notebook ของตัวเองให้เป็นชื่อแยกตามบท โค้ดที่แก้และบันทึกการทดลองจะได้หาเจอ
- กราฟและโมเดลถูกสร้างใน `outputs/` ใต้ working directory ปัจจุบันของ notebook อ่านชื่อไฟล์จาก output ของแต่ละบทได้
- ใน Colab ให้ดาวน์โหลดไฟล์ใน `outputs/` ที่ต้องการก่อนจบ session การบันทึก notebook ไม่ได้บันทึกไฟล์ทั้งหมดในเครื่อง runtime ไปด้วย
- บท 16 มีทั้งการฝึก บันทึก และโหลดโมเดลมาทำนายอยู่ใน Python block แล้ว คำสั่ง CLI เพิ่มเติมเป็นทางเลือกสำหรับผู้ที่ clone repo

## เมื่อรันไม่ได้

| อาการ | เริ่มตรวจตรงนี้ |
|---|---|
| `No module named sklearn` | ชื่อตอนติดตั้งคือ `scikit-learn`; รัน cell ติดตั้ง แล้ว restart และรันบท 00 ใหม่ |
| `No module named pip` | ถ้าใช้ environment ของ repo ที่จัดด้วย uv ให้ใช้ `uv sync --frozen` ใน terminal ตาม [setup](setup.md) |
| `NameError` | คัดลอกส่วน import/ฟังก์ชันครบหรือไม่ แล้วรันตั้งแต่ต้น |
| `SyntaxError` ที่ `uv run` หรือ `git clone` | เป็นคำสั่ง terminal ให้คัดลอกเฉพาะ Python block ของบท |
| `In [*]` หรือปุ่มกำลังประมวลผล | รอ cell ทำงานจบก่อนรันซ้ำ บางบทค้นพารามิเตอร์หรือสร้างภาพหลายรอบ |
| ไม่เห็นหน้าต่างกราฟ | ดูกราฟใต้ cell หรือเปิด PNG ใน `outputs/` |
| ผลต่างจาก README เล็กน้อย | ตรวจรุ่นแพ็กเกจและ seed; floating point อาจต่างกันระหว่างเครื่อง |

ถ้ารันผ่านแล้ว การเริ่มเรียน ML ไม่ต้องรอให้เข้าใจวิธีจัด environment ทุกแบบ กลับมาอ่าน [คู่มือตั้งเครื่อง](setup.md) เมื่อต้องการติดตั้งใหม่ แยกโปรเจกต์ หรือแก้ปัญหา kernel

## Jupyter หรือ Colab

Jupyter ใช้ทรัพยากรเครื่องที่เปิดใช้งาน ส่วน Colab ใช้ runtime ที่บริการจัดให้ โค้ดตัวอย่างของหลักสูตรใช้ข้อมูลขนาดเล็กและ CPU จึงเลือกตามความสะดวกได้ ความเร็วขึ้นกับเครื่อง/runtime และแต่ละ algorithm; ไม่ได้มีผลทดสอบที่รับรองว่าโปรแกรมหนึ่งเร็วกว่าทุกกรณี

Colab ต้องเชื่อมต่อบริการและมีข้อจำกัดอายุ session/ทรัพยากรที่อาจเปลี่ยนได้ ดู [Colab FAQ](https://research.google.com/colaboratory/faq.html) ผลตรวจอัตโนมัติของ repo ทำบน environment ในเครื่องและ CI; ไม่ใช่การรับรองการรันบน Colab ทุก runtime อ่าน [ขอบเขตผลตรวจ](verification.md)
